- **HarmonyX** source `217cc408cc3909ee67c727a2d782bede84f6c2b1` (2026-07-08): `WritePrefixes` visits prefixes before branching on the combined `runOriginal`; false does not itself skip later prefixes. [PatchSorter.cs:28–35,107–123](https://github.com/BepInEx/HarmonyX/blob/217cc408cc3909ee67c727a2d782bede84f6c2b1/Harmony/Internal/PatchSorter.cs#L107-L123), [FinalizerPatches.cs:109–141,197–247](https://github.com/BepInEx/HarmonyX/blob/217cc408cc3909ee67c727a2d782bede84f6c2b1/HarmonyTests/Patching/FinalizerPatches.cs#L109-L247).

## Recommendations derived from those facts

- Keep game reads/authority checks on the main thread; send immutable detached values to bounded background work. Queue bounds must include bytes/concurrency, overflow behavior and session cancellation—not just item count.
- Never synchronously wait on context-dependent work from Unity; coroutines do not make blocking I/O asynchronous. Observe async tasks, contain unavoidable `async void` failures, and remember synchronous work precedes the first incomplete await.
- Logging must not run arbitrary sinks under state locks, recurse on failure, dump credentials/config or block gameplay. Prefer the established log source, bounded transition records and explicit suppression counters.
- Resolve exact patch targets and record actual loaded Harmony identity. Inventory with `GetPatchInfo`, not by invoking factories/gameplay. Preserve original exceptions; use `__runOriginal` according to the observed semantic, not as universal proof nothing happened.
- Separate plugin/session lifetimes; detach exact delegates; stop admissions and fence late completions before disposal. Never synchronously drain work that needs Unity while blocking Unity.
- Tests prove only their boundary: pure/stub tests cannot establish real Mono/Harmony coexistence or game-loop liveness. Compile actual references, then perform separately authorized minimal runtime checks.
- Record source/toolchain/reference/dependency hashes and artifact digest. Hashes verify against a trusted manifest; they are not signatures. Do not copy target frameworks or license-restricted implementations blindly.
